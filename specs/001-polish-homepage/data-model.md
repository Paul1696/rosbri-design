# Data Model: Polish Rosbri Design Homepage

This feature introduces no database or persistent schema. Homepage content is a read-only
projection of the existing catalogue, taxonomy, and static editorial configuration.

## Product

Authoritative source: `window.ROSBriCatalog` in `catalog-data.js`.

| Field | Meaning | Validation |
|-------|---------|------------|
| `id` | Stable product identity and destination key | Required and unique in the catalogue |
| `title` | Customer-facing product name | Required; fallback label only for defensive rendering |
| `category` | Existing catalogue category label | Must resolve through canonical taxonomy |
| `price` | Existing customer-facing price or quote label | Display exactly when available |
| `image` | Existing product image path | Must resolve to a project asset before selection |
| `description` | Existing product description | Optional on homepage cards |
| `colorVariants` | Existing product variants | Outside homepage display scope |

## Product Universe

Authoritative source: `window.ROSBriTaxonomy.definitions` in `js/taxonomy.js`.

| Field | Meaning | Validation |
|-------|---------|------------|
| `id` | Canonical category identifier | One of the six existing taxonomy IDs |
| `label` | Existing French category label | Must come from taxonomy |
| `destination` | Filtered catalogue route | Generated by existing taxonomy URL behavior |
| `representativeImage` | Existing product/editorial image for the universe | Must exist and preserve intended composition |
| `active` | Whether the universe has displayable catalogue content | Consumer universe shown only when active |

Relationships: a Product belongs to one resolved Product Universe. The enterprise universe is
presented by the dedicated B2B section rather than duplicated in the consumer-universe grid.

## Featured Selection

Homepage-only configuration that references existing Products; it does not duplicate product
data.

| Field | Meaning | Validation |
|-------|---------|------------|
| `preferredProductId` | Curated existing product reference | Use only when product exists and has an image |
| `fallbackUniverseId` | Category used if preferred item is unavailable | Must resolve through taxonomy |
| `badge` | Optional concise merchandising label | Must not replace product truth or price |
| `position` | Stable editorial ordering | Unique positive integer within selection |

Lifecycle: resolve preferred product → if invalid, choose deterministic valid product from the
fallback universe → if no valid product exists, omit that slot without leaving an empty card.

## Hero Composition

Static presentation configuration using existing assets.

| Field | Meaning | Validation |
|-------|---------|------------|
| `message` | Primary value proposition | Concise, French, legible at all breakpoints |
| `primaryAction` | Catalogue entry action | Exactly one dominant existing destination |
| `secondaryAction` | Optional customization action | Existing modal only; visually subordinate |
| `desktopVisual` | Optimized art-directed composite | Preserves composition without deformation |
| `mobileVisual` | Simplified contained product visual | Must not overlap essential text or actions |

## Brand Story

Static editorial content containing an eyebrow, heading, concise body copy, optional existing
destination, and editorial image. It communicates modern design, African inspiration, textile
expression, and lifestyle without adding unsupported claims.

## UI States

- **Loading**: product media regions reserve stable space while the catalogue becomes available.
- **Ready**: valid curated products and active universes are rendered.
- **Partial**: invalid preferred products use deterministic fallbacks; missing optional price
  uses the existing quote behavior.
- **Empty**: no valid catalogue items produces one concise catalogue fallback action.
- **Reduced motion**: all content and actions remain available with non-essential motion removed.
